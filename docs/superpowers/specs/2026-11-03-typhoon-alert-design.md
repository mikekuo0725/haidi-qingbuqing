# 颱風提醒 設計

日期：2026-11-03 ／ 提出人：Michael（郭哲宏）

## 為什麼做
潛水的人在小琉球等地，颱風要來時最想知道「它在哪、往哪走、會不會吹到我」。目前網站沒有任何颱風資訊。Michael 想要的畫面：**在首頁整體台灣地圖上，颱風接近時畫出颱風的形狀和預計行進路線**。

## 目標
- 首頁台灣地圖（`src/ui/taiwanMap.js`）在**氣象署有發布颱風警報時**畫出：
  - 颱風圖示（目前位置）
  - 一個紅色七級風暴風圈（半徑用氣象署給的「七級風暴風半徑」）
  - 黃色虛線預計路線，每個預報時間一個點，點旁寫時間（例：明天、後天）
- 颱風在地圖可視範圍外時：**不縮放地圖**；在地圖邊緣畫一個指向颱風的箭頭，寫「颱風在東南方 600 公里」（方位＋離地圖中心／台灣的距離）。
- 點颱風圖示（或邊緣箭頭）跳出小卡，格式比照潛點小卡：颱風名稱、最大風速、中心氣壓、七級風半徑、預計位置與時間（小卡文字以氣象署欄位為準，欄位缺的就不顯示）。
- 沒有警報（資料為空）時**什麼都不畫、不顯示任何提示**。

## 不做（這次）
- 不改各潛點的預測米數、把握度、潛點面板、詳情頁。
- 不做推播／通知、不做歷史颱風、不做暴風圈以外的降雨資訊。
- 不加新的 Cloudflare 排程（帳號 cron 已滿，見下）。

## 反目標（做出來也算失敗）
- 沒颱風時地圖多出空白、錯誤訊息或「目前無颱風」之類的雜訊。
- 氣象署資料壞掉／金鑰失效時，整個首頁地圖畫不出來（颱風是附加層，失敗要安靜略過）。
- 公開 GitHub 倉庫裡出現氣象署金鑰。

## 限制與已知事實
- 資料來源：中央氣象署開放資料 **W-C0034-005**（現行颱風警報與路徑，無颱風時資料為空，颱風期間約每小時更新）。授權 OGDL，畫面要標示「資料來源：中央氣象署」。
- 小幫手（`worker/`）已有氣象署金鑰（`env.CWA_KEY`），本專案的 `opendata.cwa.gov.tw` 請求格式見 `worker/src/cwa.js`、`worker/src/buoy.js`。
- **Cloudflare 免費帳號 cron 已滿**（只剩 2 個，已被預報和每小時用掉），所以**不新增排程**。做法由 Michael 認可的方向：小幫手新增 `/v1/typhoon`，被呼叫時即時抓氣象署、用邊緣快取（約 5～10 分鐘）擋重複請求；不寫 KV 定時更新。（這是我的做法選擇，不是 Michael 指定的；也可改成併進每小時 cron，由建置者評估外部請求數。）
- 小幫手每日衛星更新已用 35/50 個外部請求（每次 scheduled 呼叫的上限），颱風請求走 fetch 路徑，不吃這個額度。
- **現在沒有颱風**，拿不到真實資料。Michael 同意：照說明文件寫，用假資料（fixture）做測試；真颱風來時才會驗證。因此解析器要寬鬆（欄位缺漏不炸）。
- 網頁在 `src/`，小幫手在 `worker/`，測試在 `test/`（現有約 342 個測試），部署流程見 repo README（小幫手要 `--config wrangler.toml`）。
- 內建瀏覽器視窗 rAF 不會跑，動畫測試用 setTimeout 代替（若颱風圖示有轉動動畫）。

## 交給建置者決定
- 颱風圖示的實際畫法（比照示意圖 B：紅圓＋白色漩渦）、顏色深淺、虛線樣式。
- 邊緣箭頭的位置演算法、距離計算方式（大圓距離即可）。
- 氣象署回傳欄位的對應（名稱、風速、氣壓、座標、預報時間）：以官方資料說明為準，寫成寬鬆解析。
- 多個颱風同時存在時，全部畫出；小卡各自對應。
- 資料抓取失敗或過舊時的處理（建議：靜默不畫）。

## 做完的樣子
1. 用假資料（有颱風）：首頁地圖看得到圖示、風圈、路線；點圖示出小卡；颱風在地圖外時出現邊緣箭頭和距離。
2. 用假資料（空）：地圖和現在完全一樣。
3. 氣象署失敗：地圖和現在完全一樣，主控台不報錯到影響使用。
4. 既有測試全過，新增解析與距離／方位的測試。
5. commit + push；**上線等 Michael 說**（上線順序：小幫手 → 網頁）。
