## 1. 要做什麼

一個手機網頁。出發前打開，就能看到潛點每一區**明後天海底大概看得到幾米**。

- 第一版只做**小琉球**，分 4 區（北、東、南、西）。
- 長期目標：全台灣 → 全世界的潛點。所以潛點要做成「潛點清單」，加潛點 = 加一筆資料，不改程式。
- 使用者：Michael、潛伴、分享給其他潛水的人。
- 做得到「預測」，做不到「保證」。畫面要老實顯示範圍跟把握度。

## 2. 架構：4 塊積木

```
手機打開網頁
   ├─→ ① 天氣資料（Open-Meteo，網頁直接拿）
   ├─→ ② 衛星小幫手（Cloudflare Worker）→ NOAA 衛星資料
   ├─→ ③ 網頁自己算分數 → 秀出 4 區卡片
   └─→ ④ 回報資料庫（Firebase Firestore + 匿名登入）
```

| 積木 | 做什麼 | 放哪裡 |
|---|---|---|
| 網頁 | 抓資料、算分數、顯示、定位、回報表單 | Cloudflare Pages（https） |
| 天氣資料 | 浪高、浪向、浪週期、風速風向、上游雨量、**海流流速流向、水溫、潮位曲線** | Open-Meteo（免費、免帳號、允許網頁直接讀；海洋資料用 Marine API） |
| 衛星小幫手 | 代抓 NOAA Kd490，算每區底分，一天抓一次存起來 | Cloudflare Worker |
| 回報資料庫 | 存潛伴回報 | Firebase Firestore |

### 為什麼要衛星小幫手
- NOAA 伺服器沒開放別的網站直接讀（沒有 CORS 標頭），手機網頁拿不到。
- 小幫手一天只抓一次，存起來給所有人用，不會一直打擾 NOAA。

### 衛星資料
- 資料集：`noaacwNPPN20S3AkdSCIDINEOF2kmDaily`（coastwatch.noaa.gov/erddap；2 公里一格；補過雲洞）。
- 2026-09-27 實測：最新資料只到 9/15（慢約 12 天）。所以衛星**只當背景**：「最近 30 天，這一區平常多清」。每天的變化交給天氣算。
- 以後想換更新的衛星（歐洲 Copernicus、日本向日葵），只要改小幫手，網頁不用動。

### 海流資料
- 第一版用 Open-Meteo 的 `ocean_current_velocity`（km/h）跟 `ocean_current_direction`（往哪流）。
- 限制：約 10 公里一格，分不出小琉球 4 邊各自的流，只代表「整片海」。畫面上要寫清楚。
- 2026-09-27 對照：Open-Meteo 約 0.5 m/s、氣象署約 0.8 m/s。第一版門檻設保守；氣象署海流預報（`M-B0071-000`，要金鑰）之後再加進來比對。

## 3. 潛點清單

每個潛點一筆資料，放在一個 JSON 檔裡。

```jsonc
{
  "id": "xiaoliuqiu",
  "name": "小琉球",
  "center": [22.34, 120.37],
  "thresholds": { "purple": 20, "green": 12, "yellow": 6 },   // 米
  "rainPoints": [ /* 上游雨量要看的點，例：旗山、六龜、三地門 */ ],
  "riverBearing": 45,                  // 河口在潛點的哪個方位（度）；小琉球：高屏溪口在東北
  "safety": { "currentYellowKn": 0.5, "currentRedKn": 1.0, "waveRedM": 1.5 },
  "zones": [
    {
      "id": "west",
      "name": "西邊",
      "location": [22.34, 120.35],     // 用來算「你在哪一區」
      "facing": 270,                   // 面向哪邊（度，北=0）
      "shelter": "open",               // open 開放 / semi 半開放 / bay 灣內
      "bottom": "rock",                // sand 沙底 / mixed 混合 / rock 礁岩（沙底最怕浪）
      "riverImpact": 0.3,              // 河口泥水影響多大（0~1）
      "satBox": [[22.32, 120.31], [22.36, 120.34]],  // 衛星取樣範圍（離岸 2~4 公里）
      "fallbackBase": 12               // 衛星抓不到時的保守底分（米）
    }
    // 北、東、南 …
  ]
}
```

- 不是小島的潛點（墾丁、東北角）一樣用這個格式：沿海岸切成幾段，每段填它面向哪邊。算法完全一樣。
- 表內的數字（面向、影響程度、上游雨量點、底分）第一版先用估的，之後用回報調。

## 4. 分數怎麼算：先拿底分，再打折

### 步驟 1：底分（衛星）
- 每區最近 30 天的 Kd490，取中間值。
- 換算米數：`底分 = c ÷ Kd490`。`c` 先設 1.5（Kd 0.1 ≈ 15 米），之後用回報調。
- 衛星沒資料 → 用 `fallbackBase`，範圍變寬。

### 步驟 2：打折（天氣，看白天 08~16 點）
| 線索 | 怎麼看 | 打折方向 |
|---|---|---|
| 🌊 湧浪 | 浪向跟這區面向差幾度（越正對越慘）、浪高、**浪週期**（越長越慘） | 灣內再減輕；沙底加重、礁岩減輕 |
| 🌊 前幾天的浪 | 前 3 天最大的浪（一樣看有沒有正對這區），越久以前影響越小（前 1 天全算、前 2 天算一半、前 3 天算 1/4） | 大浪退了水要 1~3 天才清；用 Open-Meteo `past_days` |
| ☁️ 雲量 | 白天平均雲量高 → 小扣（最多打 9 折） | 陰天光線暗，看起來比較近 |
| 🌬️ 風 | 風從海吹向這區 → 扣；從島上吹出去 → 小加分 | |
| 🌧️ 河口 | 上游前 3 天雨量加總 × 這區的 `riverImpact` | 小琉球：東、北最慘 |
| 🌙 潮汐 | 大潮（滿月、新月前後）→ 小扣 | 用月相算 |
| 🌀 海流方向 | 流從河口那邊往這個潛點流 → 河口扣分加重；從外海流過來 → 小加分 | 每個潛點記「河口在哪個方位」 |
| 🌀 海流速度 | 中等的流（0.3~0.8 節）→ 小加分（把顆粒沖走）；很強的流（1 節以上）＋ 沙底 → 扣分（攪起沙） | 礁岩區很強的流不扣 |

- 每一項是一個 0~1.1 的倍數。所有倍數乘起來 × 底分 = 預測米數。
- 折數的表格放在設定檔，不寫死。

### 步驟 3：輸出
- **範圍**：預測米數 × 0.75 ~ × 1.15（把握度低時再放寬）。
- **燈號**（用範圍中間值）：🟣 20 米以上、🟢 12~20、🟡 6~12、🔴 6 以下。門檻放在潛點清單裡，每個潛點可以不一樣。
- **原因**：扣最多的那一項，例如「湧浪正對西邊」。
- **把握度**：高（衛星＋天氣都有，最近有人回報）／中（少一個）／低（兩個都靠備用數字）。
- **跟平常比**：預測米數 vs 底分。高 15% 以上 →「比平常清 ↑」；低 15% 以上 →「比平常濁 ↓」；其他 →「跟平常差不多」。

### 步驟 4：安全提醒（跟能見度分開算）
「很清」不等於「可以潛」。海流用**節**顯示（潛水員習慣的單位）：

| 流速 | 燈 | 顯示 |
|---|---|---|
| 0.5 節以下 | 🟢 | 輕鬆 |
| 0.5~1 節 | 🟡 | 注意 |
| 1 節以上 | 🔴 | ⚠️ 流強，建議放流潛或換時段 |

- 加一個箭頭說往哪流，例：「→ 往東北」。
- 浪高超過潛點設定的上限（小琉球先設 1.5 米）也亮 🔴「浪大，不建議下水」。
- 門檻放在潛點清單裡。

- **湧升流提醒**：水溫比前 3 天平均低 2°C 以上 → 資訊列顯示「🥶 水溫突降，可能有湧升流，幾天後水可能變綠」。第一版只提醒，不扣分。

### 步驟 5：最佳下水時段
- 看白天 08~16 點每個小時：流越弱越好（用潮位曲線找平潮前後）＋ 越接近中午光線越好。
- 挑分數最高的連續 2 小時，例：「最佳時段 10~12 點（平潮）」。

## 5. 畫面

### 主畫面：卡片清單
- 上面：潛點名稱、更新時間、「今天／明天／後天」切換。
- 定位列：「📍 你現在在小琉球西邊」或「📍 你離小琉球 65 公里」。
- 潛點資訊列（整片海共用）：🌀 海流（節數＋箭頭＋安全燈）、🌡️ 水溫、⏰ 最佳下水時段。
- 4 張卡片，**由好到壞排序**。每張：燈號、區名、米數範圍、原因、跟平常比（↑↓）、把握度、「今天 N 人回報：幾米」。你所在的那區標「你在這裡」。
- 最下面：「我下水了，回報能見度」按鈕、「分享給潛伴」按鈕。
- 頁尾：**每個資料來源多新**，例：「天氣 06:00 更新・衛星 9/15・回報 2 小時前」。

### 卡片細節頁（點一張卡片進去）
- 標題：區名、燈號、米數範圍、日期、把握度。
- 「怎麼算出來的」：平常底分（衛星最近 30 天）→ 每一項打折用長條圖＋倍數顯示（扣越多條越長）→ 最後約幾米。
- 「最近回報」：這一區最近的回報（米數、深度、時間、暱稱、想說的話）。
- 「這一區」：面向、遮蔽程度、底質。
- 畫面參考：`.superpowers/brainstorm/` 裡的 `full-preview.html`。

### 分享
- 用手機內建的分享（Web Share API），可以直接選 LINE。
- 分享內容是一段文字＋網址，例：「明天小琉球：西邊 🟣 20~26 米、南邊 🟢 14~18 米｜流 0.3 節 🟢｜水溫 28°C｜最佳 10~12 點 👉 網址」。
- 手機不支援內建分享 → 改成「複製文字」。

### 定位
- 打開網頁時問定位。允許 → 找離你最近的區（用每區的 `location` 算距離）。
- 離潛點太遠（例如 > 15 公里）→ 只顯示距離。
- 不允許或抓不到 → 不顯示，其他照常。
- **位置只在手機上算，不存、不送出。**
- 以後多潛點時：自動選最近的潛點。

### 回報表單
1. 哪一區（預設：你所在的區）
2. 看到幾米：按鈕 `3` `5` `8` `10` `15` `20` `25` `30+`
3. 大概幾米深：按鈕 `5` `10` `15` `20` `30+`（表層跟深處能見度常常不一樣，以後調分數用）
4. 下水時間（預設現在）
5. 暱稱（第一次輸入，之後記住）
6. 想說的話（選填）

- 不用登入。背後用 Firebase 匿名登入（手機自動拿一個看不到的代號），擋亂灌。
- 送出時同時存「當下的預測快照」：底分、每項折數、預測米數。以後拿來比對調參數。
- 只存「哪一區」，不存精準位置。

## 6. 有人回報後怎麼越來越準

參考氣象界的「偏差修正」（MOS、卡爾曼濾波）：一直比對「猜的 vs 真的」，自動修掉系統性的偏差。第一版做前 2 步。

### 第 1 步：當天即時修正（只影響「今天」）
- 今天這一區有人回報 → 顯示的米數往回報靠近：
  `顯示 = 預測 × (1 − w) + 回報中間值 × w`
- `w` = 回報人數越多越大（1 人 0.3、2 人 0.5、3 人以上 0.7），距離回報時間每 3 小時減半。
- 卡片原因改寫成「依今天 2 人回報調整」。

### 第 2 步：每區自動修正（每天算一次）
- 衛星小幫手每天順便讀回報，算出每一區的「修正倍數」，跟衛星底分一起存起來給網頁用。
- 算法：
  1. 每筆回報：`比例 = 實際米數 ÷ 當時預測米數`（用回報裡存的預測快照，而且用「第 1 步修正前」的預測）
  2. 最近 90 天的比例取平均（新的比重大，每 30 天減半）
  3. 回報少時只修一點點：`修正倍數 = 1 + (平均比例 − 1) × n ÷ (n + 10)`，n = 回報筆數
  4. 一區少於 5 筆 → 不修（倍數 = 1）；倍數限制在 0.5~1.5 之間
- 預測米數最後再乘這個倍數。細節頁多一行：「依過去 23 筆回報，這區 ×0.88」。

### 防亂報
- 同區同一天有 3 筆以上回報時，跟中間值差超過一半的那筆，比重降到 0.3。
- 回報有存水深，第一版先不分深度；之後回報多了再比對「差不多深度」的。

### 第 3、4 步（之後做）
- 第 3 步（累積約 50 筆）：用預測快照找出是哪一項折數扣太多或太少。
- 第 4 步（累積幾百筆）：讓電腦自己學。

## 7. 出錯怎麼辦

原則：壞一塊，其他照常用，而且老實講。

| 壞掉的 | 怎麼辦 | 顯示 |
|---|---|---|
| 天氣抓不到 | 用手機上次存的結果 | 灰色燈號 +「這是 N 小時前的預測」 |
| 衛星抓不到／太舊／都被雲擋 | 用 `fallbackBase` | 範圍變寬 +「衛星資料暫缺，準度較低」 |
| 回報送不出去（船上沒訊號） | 存在手機，有網路自動補送 | 「已存好，有網路會自動送出」 |
| 定位抓不到 | 不顯示 | — |
| 數字不合理（例如浪高 50 米） | 當成抓不到 | 同「天氣抓不到」 |

## 8. 怎麼測試

1. **自動測試算法**（每次改程式都跑）：用假資料餵算法，檢查
   - 浪正對西邊 → 西邊扣最多
   - 同樣的浪，灣內扣得比開放海岸少
   - 上游大雨 → `riverImpact` 高的區扣最多
   - 燈號邊界：20 米 = 🟣、19.9 米 = 🟢、12 = 🟢、6 = 🟡、5.9 = 🔴
   - 人在西岸 → 「你在西邊」；離很遠 → 顯示距離
   - 天氣抓不到 → 灰色燈號；衛星抓不到 → 用備用底分、把握度降低
   - 流速邊界：0.5 節 = 🟡、1 節 = 🔴；km/h 換算節正確
   - 流從河口方位流過來 → 河口扣分加重
   - 最佳時段：流最弱的 2 小時被選中
   - 跟平常比：高 15% → ↑、低 15% → ↓
   - 前天大浪、今天沒浪 → 還是要扣分（比前 3 天都沒浪的扣更多）
   - 同樣的浪，沙底扣得比礁岩多
   - 陰天比晴天小扣
   - 很強的流：沙底扣分、礁岩不扣；中等的流小加分
   - 水溫比前 3 天低 2°C → 出現湧升流提醒
   - 當天修正：1 人回報 → 往回報靠 30%；6 小時後剩 1/4 效果
   - 每區修正：4 筆 → 不修；10 筆都是實際 = 預測 × 0.8 → 倍數 = 0.9；極端值被限制在 0.5~1.5
   - 防亂報：一筆離中間值差一半以上 → 比重 0.3
2. **沒有舊潛水日誌**，所以不做上線前回頭驗證。上線後靠回報。
3. **上線後每週看一次**：預測 vs 回報差多少，用來調 `c`、折數、`fallbackBase`。
   - 主要看兩個數字：①米數平均差幾米 ②「說比平常清的時候，有幾成真的比平常清」（DiveSight 用的方法，他們是 85%）。

## 9. 第一版不做（以後再說）

- 其他潛點（格式已經準備好）
- 更新的衛星來源（Copernicus、向日葵）
- 衛星看海水顏色的圖層
- LINE 通知（「明天西邊 🟣」）
- Google / LINE 登入
- 讓電腦自己學（等回報夠多再做）
- 即時影像連結（Michael 說不需要）
- 氣象署資料（海流、沿海預報）——之後拿來跟 Open-Meteo 比對
- 海洋生物預測、船班停航預估
- 小琉球浮標即時浪高、成大「水肺潛水」燈號（之後拿來比對）
- 「哪個月最適合去」、一次看 7 天、回報加照片、藻華預測
